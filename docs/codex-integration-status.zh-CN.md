# Codex 与 YouTube 接入核查

核查日期：2026-09-26。

## 当前接入程度

OntoKB 通过本机 `codex app-server` 的 `initialize → thread/start → turn/start` 调用模型，并消费完成事件。使用本机 Codex 的登录状态；当前 `codex login status` 确认为 ChatGPT 登录。没有指定模型时继承本机配置。

YouTube 链路是：链接识别 → yt-dlp 获取字幕 → 无可用字幕时下载音频并由 faster-whisper 本地转写 → Codex 对文字生成摘要、关键点和结构化实体关系 → ontology 校验 → SQLite 与 vault 入库 → 根据正文与图谱回答。

文章入口直接把用户粘贴的正文送入同一提取流程。“新建摘要”弹窗新增 Chat 入口，打开现有 Chat 抽屉；切换时保留文章草稿。

## 实际发现与验证

- `XAujxrtd4uI` 缓存来源为 `faster-whisper:small`，时长 3,486 秒，正文 21,167 字符。文本有明显语音识别错误，不能视为校对稿。
- `rHmQ_v7OpY4` 缓存来源标记为 `caption:zh-Hans`，时长 1,548 秒，但所谓正文的 940 字符实际是 `#EXTM3U` 字幕分段索引及下载地址。旧实现把它当作 VTT 文本处理，无法提供真实字幕。这能解释只获得题目信息的体验，但不能仅凭缓存重建过去每次模型调用的输入。
- 实际调用项目的 app-server 适配器，将第一条视频中部 1,800 字符送入模型并要求引用原文；调用成功，返回引用通过逐字包含校验。这验证了认证、协议、正文传递和结构化响应，而非仅检查 CLI 是否存在。
- 随后从浏览器 Chat 提交第一条视频链接，询问标题没有提及的 Vision Pro 定价观点。界面显示实际发送全部 21,167 字符，模型给出降价、补贴和销量规模的具体观点及原文引用；完整的 Chat → API → 正文缓存 → Codex → UI 链路成功。共 80 项测试通过，浏览器未记录脚本错误。

## 本次修复

字幕下载识别 HLS 分段索引，逐段获取 VTT 正文；支持 JSON3 文本；下载或解析失败时继续尝试其他字幕，再回退音频转写。任何分段失败都不接受部分下载结果。缓存中的索引、HTML 错误页、空响应和纯 URL 不再当作正文。

后续发现：只检查“存在有效正文缓存”仍不足以判断摘要新旧。当前版本给分析结果记录正文 SHA-256、字符数和分析版本；只有指纹一致才复用。缺失或不同会重新分析。强制重分析在提取成功后备份 SQLite / vault，以事务替换该来源的关系，并清理该来源独有且已无关系的旧节点；其他来源保留。写入失败回滚数据库和已触及的笔记，崩溃恢复使用备份。

Chat 展示正文字符数、实际发送字符数及截断状态。健康提示改为“已检测到 Codex CLI”，不再将二进制存在误述为认证或视频获取成功。

## 尚未接入的能力与限制

- Codex 接收文字；没有直接观看视频画面、OCR、画面时间轴或原始音频输入。
- 普通提取模式仍只处理提供的文字。Chat 执行助手通过 app-server 动态工具调用宿主：列出资料、读正文／检查分析版本、查图谱、重新分析并回写、同步笔记。宿主执行写入并回读验证；不开放任意 shell、文件修改或桌面控制。字幕下载仍由 OntoKB 执行。
- 每次模型调用仍新建 app-server 进程和会话，但 Chat 请求现携带最近 10 轮已完成的用户／助手消息（最多 32,000 字符），作为对话上下文传入模型。超限按最旧的完整轮次淘汰。历史不是系统指令或事实证据。视频追问会复用最近用户链接对应的已入库视频及正文；不会仅因历史中出现未入库链接而自动采集。点击“新对话”或刷新页面会清空历史；暂不跨重启持久化。
- 提取和视频问答最多传入前 150,000 字符，尚未实现超长内容分块汇总。字符数不能证明字幕覆盖完整视频。
- 默认 Whisper 语言为中文；其他语言应配置 `whisper_language: auto` 或相应语言。字幕权限、限流、网络、模型下载和转写误差仍会影响结果。
- 已完成读取正文的真实模型测试；HLS 分段解析通过模拟网络回归测试，未对每个 YouTube 视频进行真实下载验证。
- Electron 通过安装目录的 `runtime.json` 指向此项目并加载同一 localhost 后端，前端无独立副本。更新后端需重启服务；界面刷新即可读取新前端。

官方协议参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。具体已启用能力以项目 `src/ontokb/codex_backend.py` 为准，不能从 app-server 的全部能力反推本项目已全部接入。
